## 一、拖拽安排时自动展开日历

### 目标

任务包面板展开时开始拖拽，自动把面板收纳到窄栏，让月、周、日视图获得更大的可见区域；拖拽完成后恢复任务包面板。

### 实现

- `CalendarTab.handleDragStart()` 记录拖拽前面板状态，并用 220ms 缓动动画将任务包面板从 30% 收纳到 10%。
- 收纳后的窄栏在拖拽期间改为浅红色“取消安排”区域，使用红色虚线边框；拖拽进入时背景加深。
- 将任务包放到“取消安排”区域会清空拖拽目标、虚线预览及高亮状态，并提示“已取消安排”。
- 成功放入日历、日期重复、目标时段已满或拖拽在其他位置结束时，都会统一清理拖拽状态；从展开面板发起的拖拽随后自动恢复展开。
- 拖拽成功与取消共用 `finishPackageDrag()`，避免不同结束路径出现面板无法恢复的问题。

## 二、删除单条日历安排

- 已安排任务包的详情页标题右侧，在通知按钮旁新增红色“删除”按钮。
- 点击后删除当前 `ScheduledEvent` 并关闭详情页，只删除这一次日历安排，不删除任务包模板，也不影响同一模板安排在其他日期的记录。
- `ScheduleStore.removeEvent()` 现在会主动通知订阅者，删除后月视图标记及周/日视图事件块立即刷新。

## 三、开始时间调整

- 原来的“`xx:xx · xx 分钟`”文本拆成两个左对齐的小按钮。
- 点击开始时间按钮展开 24 小时制 `TimePicker`，小时和分钟可像闹钟一样分别滑动。
- 选择器归位后立即更新当前日程的 `startHour/startMinute/endHour/endMinute` 并持久化，日历事件块同步移动。
- 若选择的时间会让任务跨过当天末尾，则自动吸附到当天最晚可开始时间并提示用户。
- 调整后若会使同一重叠组出现第三个任务，则拒绝保存，保持原时间。

## 四、单步时长与总时长调整

- 点击“`xx 分钟`”按钮展开二级调整面板。
- 每一行显示“`步骤x：步骤名  原时长 → 当前时长`”，通过 `− / +` 以 5 分钟为单位调整；每一步最短保留 1 分钟。
- 面板底部显示“`总时长 原时长 → 当前时长`”。总时长调整以打开详情时的原始步骤比例重新分配，并由最后一步补齐取整误差，因此会覆盖此前的单步调整。
- 步骤调整仅写入当前 `ScheduledEvent.steps` 的深拷贝，不修改 `TaskPackage` 模板。
- 每次调整都会同步重算结束时间并持久化；日历块的高度、步骤摘要和结束时间实时刷新。
- 总时长不能超过当天剩余时间，也不能形成第三个重叠日程。

## 五、数据与刷新链路

- `ScheduleStore` 新增统一的 `canPlaceInterval()`，拖拽安排、时间轴拉伸和详情页编辑共用同一套“最多两个重叠日程”规则。
- 详情页所有编辑都先创建显式类型的 `ScheduledEvent` / `TaskStep` 深拷贝，避免修改任务包模板或触发 ArkTS 未声明对象字面量限制。
- `ScheduleStore.updateEvent()` 的既有通知机制驱动 `CalendarTab.loadData()`，日程移动和缩放不需要关闭详情页后再刷新。

## 九、跨月样式刷新与固定日期标题（2026-09-30）

### 跨月置灰错误

- 原月视图以 `dateStr` 作为 `ForEach` 键。相邻月份会共享日期，例如 `2026-10-01` 在九月视图中是灰色的下月填充格，在十月视图中则是正常当月格；键不变时 ArkUI 会复用旧 `GridItem`，从而保留错误的 `isCurrentMonth` 样式。
- 月历格子的键改为“当前视图年 + 当前视图月 + 格子索引 + dateStr”。切换月份后 42 个格子会按新月份身份重建，因此十月日期恢复正常颜色，九月尾部日期正确置灰。

### 固定日期标题

- 新增月、周、日视图共用的固定标题栏，放在日期网格或时间轴 `Scroll` 之前，因此不会随时间轴滑动消失。
- 月视图显示 `xxxx年xx月`，例如 `2026年10月`；新增标题后，星期一至星期日标题行整体下移。
- 周视图显示 `xxxx年第xx周`，例如 `2026年第40周`。
- 日视图显示 `xxxx年xx月xx日`，例如 `2026年09月30日`。
- 原导航栏中央的重复日期文字改为空白弹性区，保留上一页、今天、视图切换和下一页按钮，避免标题重复。

## 十、日期标题位置修正与农历信息（2026-10-01）

- 上一版把日期标题放在导航栏之前，视图容器又固定占满右侧高度，标题可能被父布局顶部裁切，因此实际界面中无法看到。

- 标题栏高度由 `46vp` 缩小到 `30vp`，主标题字号由 `22vp` 缩小到 `16vp`，减少对日历可用空间的占用。
- 月视图的星期标题行位于日期标题下方，因此布局顺序现在是“导航行 → 日期标题 → 星期行 → 月历网格”。

- 日视图在公历日期后追加完整农历月日，例如“农历八月廿一”。
- 周视图按需求只显示公历年份和周数，不追加农历信息。

## 十二、真机启动 JS Crash 修复（2026-10-01）

### 崩溃现象与定位

- 真机崩溃日志：`jscrash-com.example.colendar-20261001095602.100.txt`。
- 错误为 `TypeError: Cannot read property length of undefined`，首个业务栈位于 `CalendarTab.ets` 的 `buildFixedDateHeader()`。
- 原标题 Builder 使用两个位置参数 `title` 与 `lunarTitle`。ArkTS 编译能够通过，但真机 ArkUI 初次渲染时第二个位置参数未被可靠传入，导致执行 `lunarTitle.length` 时直接崩溃；进程启动约 3 秒后退出。

### 修复

- 新增显式 `DateHeaderOptions` 类，统一保存主标题和副标题。
- `buildFixedDateHeader()` 改为只接收一个 `DateHeaderOptions` 参数，月、周、日三种调用全部通过类实例传值，不再依赖第二个位置参数。
- 副标题始终初始化为字符串；周视图使用空字符串，因此条件渲染时不会访问 `undefined.length`。

### 验证

- 完整执行 `assembleHap`，ArkTS 编译、HAP 打包、检查和签名全部通过，结果为 `BUILD SUCCESSFUL`。
- 该编译验证确认类型与构建链路正常；仍建议在原真机上重新安装并启动一次，确认首屏不再生成同类 JS Crash。

## 十三、第二次真机 JS Crash 与最终参数移除（2026-10-01）

### 第二份崩溃日志

- 日志：`jscrash-com.example.colendar-20261001095939.000.txt`。
- 错误仍为 `Cannot read property length of undefined`，但位置已移动到 `options.subtitle.length`，证明新 HAP 已安装运行，也证明上一次使用普通类包装参数仍不足以解决真机 Builder 参数桥接问题。
- `options` 本身存在，但其中的 `subtitle` 字段在真机渲染阶段为 `undefined`；因此问题不在干支计算结果，而在参数对象进入 `@Builder` 后的字段传递。

### 最终修复

- 删除 `DateHeaderOptions` 及所有标题 Builder 实参。
- `buildFixedDateHeader()` 改为零参数 Builder，直接读取组件内部的 `fixedDateHeaderTitle` 与 `fixedDateHeaderSubtitle` 计算属性。
- 两个计算属性根据当前 `viewMode` 返回月、周、日对应文本，并保证副标题在周视图中明确返回空字符串。
- 这样标题渲染不再经过 ArkUI Builder 参数桥接，消除了两次崩溃共同依赖的 `undefined.length` 来源。

### 验证

- 再次完整执行 `assembleHap`，结果为 `BUILD SUCCESSFUL`。
- 本地构建只能确认编译和打包；最终运行验证仍需安装本次新 HAP 后在原真机启动。

## 十四、第三次真机 JS Crash 与共享 Builder 移除（2026-10-01）

### 第三份崩溃日志

- 日志：`jscrash-com.example.colendar-20261001100255.867.txt`。
- 错误仍为 `Cannot read property length of undefined`，这次准确落在零参数 Builder 内的 `this.fixedDateHeaderSubtitle.length`。
- 这证明问题并非只发生在 Builder 入参：该真机版本的 ArkUI 增量渲染转换在这个共享 Builder 的条件分支中，对计算属性的读取同样出现了 `undefined`。前两次修复只改变了数据进入 Builder 的方式，没有移除真正持续出错的共享 Builder 更新闭包。

### 最终结构调整

- 完全删除共享的 `buildFixedDateHeader()`，同时删除仅供它使用的 `fixedDateHeaderTitle` 和 `fixedDateHeaderSubtitle` 计算属性。
- 月、周、日视图分别在自己的内容 Builder 中直接声明标题 `Row`，直接绑定 `monthLabel/monthGanZhiLabel`、`weekTitleLabel`、`dayDateLabel/dayTraditionalLabel`。
- 删除标题路径中所有基于动态副标题执行的 `.length` 判断；周视图直接不创建副标题 Text。
- 标题的位置、30vp 高度、主副标题字号与颜色保持不变，仅改变渲染结构。

### 验证

- 搜索确认 `fixedDateHeader` 与 `buildFixedDateHeader` 已从 `CalendarTab.ets` 完全移除。
- 完整执行 `assembleHap`，结果为 `BUILD SUCCESSFUL`。
- 需要安装这一版新 HAP 做最终真机验证；若仍有 Crash，新的堆栈将不可能再指向已经删除的 `buildFixedDateHeader()`。

## 十五、日期标题空白的真机根因与最终修复（2026-10-01）

### 真机证据与根因

- 通过 HDC 在测试手机上采集月视图布局树和截图，确认标题所在的 `30vp` 行真实存在，但 `2026年10月` 与干支副标题的 `Text` 节点完全没有进入布局树；因此问题不是遮挡、颜色或层级，而是数据绑定没有生成文字节点。
- 共享 Builder 被移除后，月、周、日标题仍直接绑定 `get monthLabel()` 等计算属性。该真机 ArkUI 增量渲染转换没有稳定追踪这些 getter：渲染表达式得到未定义值时，空行仍保留，但文字节点不生成；在其他组合中还可能触发 `undefined.length`。

### 修复

- 新增五个显式响应式标题状态：`monthHeaderTitle`、`monthHeaderTraditional`、`weekHeaderTitle`、`dayHeaderTitle`、`dayHeaderTraditional`。
- 新增 `refreshCalendarHeaderTitles()`，只根据 `currentYear/currentMonth/currentWeekStart/selectedDateStr` 等原始状态直接计算标题，不再从任何标题 getter 间接取值。
- 在首次进入、月/周/日视图切换、前后月、前后周、前后日、回到今天以及点击日期进入日视图的路径中统一刷新标题状态。
- 干支与农历计算加入异常降级：系统农历能力异常时只清空副标题，公历主标题和页面启动不受影响。
- 月、周、日标题 `Text` 全部改为绑定上述 `@State` 字符串。

### 构建与真机验证

- 完整执行 `assembleHap`，结果为 `BUILD SUCCESSFUL`。
- 将签名 HAP 覆盖安装到测试手机后，应用进程保持运行，不再启动即退出。
- 月视图截图和布局树均确认显示 `2026年10月` 与 `丙午年·丁酉月—戊戌月`。
- 真机切换到周视图后，布局树确认显示 `2026年第40周`。
- 真机切换到日视图后，布局树确认显示 `2026年10月01日` 与 `丙午年·丁酉月·廿一`。
