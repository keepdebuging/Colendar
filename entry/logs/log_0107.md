**关键技术点**

## 第 3 次迭代（log_03 · 2026-06-29）—— CalendarTab 组件完善

**目标**：对 CalendarTab 做一轮「修整式」完善，解决 6 个问题，不改数据模型。

**核心改动**

1. **代码结构重组**：成员按 `@Prop → @State → 私有字段 → 计算属性 → 生命周期 → 数据加载 → 日历计算 → 导航 → 拖拽 → build → @Builder` 顺序排列（`activeDragPkgId` 从 633 行移到声明区）。

2. **「今天」按钮**：`goToToday()` 重置年月 + 刷新；`isCurrentMonthToday()` 判断是否本月，本月时按钮置灰。

3. **填充格视觉区分**：非当月格子背景浅灰 `#F0F0F0`，且不响应拖拽高亮。

4. **日程查询性能优化**：`eventsDateSet: Set<string>` 预计算当月有日程日期，`hasEventsOnDate()` 从 O(N) 遍历降为 O(1) `Set.has()`；在 `loadData`/月份切换/拖拽放下/返回月视图时统一 `refreshEventsDateSet()`。

5. **拖拽数据传递完善（双通道）**：
   ```typescript
   // 发送端
   .onDragStart((event) => {
     this.handleDragStart(pkg);
     event.setData({ uniformTypeDescriptor: 'general.plain-text', data: pkg.id });
   })
   // 接收端：系统通道优先，@State 后备
   const raw = event.getData()?.['general.plain-text'];
   if (typeof raw === 'string') pkgId = raw;
   if (!pkgId && this.activeDragPkgId) pkgId = this.activeDragPkgId;
   ```

**关键技术点**：`Set` 预计算模式、拖拽双通道数据传递。

## 第 7 次迭代（log_07 · 2026-07-06）—— 时间轴分割线对齐

**目标**：周/日视图时间轴实现 `hh:mm | ——————` 视觉，核心是解决标签与分割线的对齐。

**最终方案（历经 8 版迭代）**
- **移除垂直分割线**：灰底标签区与白底内容区已有天然色块区分。
- **动态高度数组（核心）**：让时间标签与内容区使用**完全相同**的高度值。

**对齐根因**：时间标签每槽位 = 固定 `HOUR_HEIGHT`，内容每槽位 = `Divider(1vp)` + `Blank(H-1)`；每小时内容比标签多 1vp，24 小时累计漂移 23vp。

**修复方案**
```typescript
@State weekHourHeights: number[] = [];  // 周视图 24 个槽位高度
@State dayHourHeights: number[] = [];   // 日视图 24 个槽位高度

// computeWeekHourHeights / computeDayHourHeights
for (let h = 0; h < 24; h++) {
  let maxH = STANDARD_HOUR_HEIGHT;      // 周 42 / 日 60
  for (const evt of eventsOfHour(h)) {
    const eh = getTotalDuration(evt.steps) / 60 * HOUR_HEIGHT;
    maxH = Math.max(maxH, eh);
  }
  heights[h] = maxH;
}
```
周视图取 7 天中同一小时的最大事件高度；两边槽位高度相等 `H[i]` 即对齐。

**关键点**
- 防御性 fallback：`heights[h] > 0 ? heights[h] : STANDARD`（避免空数组/0 高度）
- 高度重算触发链：用户操作 → 导航方法 → `computeXXXHourHeights()` → `@State` 更新 → 标签+内容同步刷新

**追加改动（同日志内，2026-07-08）—— 周/日视图拖拽 + 预览条 + 自动吸附**
- `ScheduledEvent` 新增 `endHour` / `endMinute` 字段；导出 `getTotalDuration()`
- 周/日视图支持从左侧面板拖拽到时间轴，自动吸附
- **吸附到半小时算法**：`effectiveY = getY() + scrollOffset - topPadding` → `hourFloat = effectiveY / HOUR_HEIGHT` → `snappedMin = round(hourFloat×60/30)×30`
- **预览条**（`buildDragPreviewBar`）：半透明 `#CC333333`，格式 `"6月30日 15:00 - 15:45 健身包"`
- 已知限制：月视图无预览条；`endHour/endMinute` 跨日用 `% 24` 截断

## 关键技术点汇总（去重）

1. **单例数据仓库**：`TaskStore` / `ScheduleStore` 私有静态实例，全局一份数据。
2. **状态管理三件套**：
   - `@State`（局部）+ `@Prop @Watch`（早期）→ `@Provide/@Consume @Watch`（第 6 次起，跨 `TabContent`）
   - `_version` 字段 + `ForEach` 组合 key，解决编辑后不刷新。
3. **拖拽系统**：`.draggable` + `onDragStart/Drop/Enter/Leave`；**双通道**（`event.setData` 主 + `@State` 后备）；**自动吸附**（整点/半小时）。
4. **时间轴对齐**：动态高度数组 `H[i]` 两边共用；核心陷阱是 `Divider` 占 1vp 布局空间导致累计漂移。
5. **动画**：`animateTo({ duration, curve })` 闭包内改 `@State` 触发过渡。
6. **性能**：`Set` 预计算 `eventsDateSet` 实现 O(1) 日期查询。
7. **布局**：`layoutWeight(1)` 均分（替代不可靠的 `calc` 百分比）。
8. **CustomDialog 陷阱**：controller 默认值不可递归引用自身，用 `Column() {}` 占位符。
9. **路由**：`router.pushUrl/back/getParams`；页面需在 `main_pages.json` 注册；`CreatePackage` 用 `packageId` 参数做双模式。
10. **颜色系统**：8 色调色板 + `getNextColor` 循环分配。

## 已知限制与后续改进（汇总去重）

- **数据持久化**：所有数据仅存内存，关闭应用即丢失。→ *（后续 `log_08` 已用 Preferences 持久化解决）*
