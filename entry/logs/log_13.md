## 一、名称迁移

产品正式名称从 StudyStream / TimeCraft 调整为 **Colendar**。

名称由 `calendar` 与 `cooperate` 组合而来，表达本应用不只是记录日程，也会在用户开始任务后陪伴其完成每一个步骤。

### 已修改文件

| 文件 | 改动 |
| --- | --- |
| `AppScope/resources/base/element/string.json` | 应用显示名称改为 `Colendar` |
| `entry/src/main/resources/base/element/string.json` | Entry 模块描述和 Ability 标签改为 `Colendar` |

### 保持不变的内部标识

为避免额外引入存储格式迁移，本轮仍保持：

- 工程目录 `studystream`
- Preferences 文件名 `studystream_store`
- 既有 README、计划和历史开发日志

工程目录和存储键可以在日后单独规划迁移。

## 二、Bundle Name 迁移

- `AppScope/app.json5`：`com.example.studystream` → `com.example.colendar`
- 应用身份变更后，设备会将 Colendar 视为一个新应用；旧 StudyStream 安装包中的本地任务、日程与执行记录不会自动迁移到新包名。
- 现有签名配置文件路径未改动。若 DevEco Studio 提示签名 Profile 与 Bundle Name 不匹配，请为 `com.example.colendar` 创建或选择对应的 Profile。

## 四、已完成日程的视觉标记（2026-09-27）

- 在 `left_problem.md` 记录“查看结果进入不可操作计时页、无法重新开始”的遗留问题、原因和验收标准，本轮不改执行流程。
- 日历中的日程只要对应执行记录正常完成，即显示为已完成：月视图圆点降低透明度，周视图和日视图事件块整体降低透明度，标题增加删除线。
- 已放弃或尚未完成的执行记录不显示完成样式。
- `CalendarTab` 订阅执行仓库变化，任务完成时刷新事件块渲染；组件退出时取消订阅。
- 完成判断按“该日程历史上至少存在一次 `completed` 执行记录”计算，为后续支持重新执行保留正确语义。
- 验证：`CompileArkTS` 与 `PackageHap` 通过；`SignHap` 因改名后签名 Profile 仍绑定旧 Bundle Name 而失败，需要在 DevEco Studio 的 Signing Configs 中为 `com.example.colendar` 修复或重新生成签名配置。

## 五、再次开始与累计完成次数（2026-09-27）

- 已完成或已放弃日程的详情按钮由“查看结果”改为“再次开始”，不再进入不可操作的旧计时快照。
- `ExecutionStore.startFromScheduledEvent()` 仅复用 `running`、`paused`、`waiting-next` 会话；最近一轮处于 `completed` 或 `abandoned` 时创建新的独立会话。
- 新会话从第一步完整时长开始，旧会话继续保留在执行历史中。
- 周视图、日视图及周视图重叠卡片标题改为“任务包标题 · 已完成 x 次”；只累计 `completed`，放弃不计数。
- 新增单元测试，验证完成后再次开始会生成不同会话 ID、从第一步重新计时，并保留两条执行记录。
- `left_problem.md` 中对应问题更新为已解决，`plan.md` 同步为“不制作独立结果页、支持累计完成次数”的当前产品决策。
- 构建验证：`assembleHap` 完整通过，包含 ArkTS 编译、HAP 打包与签名。项目当前未暴露命令行单元测试任务，新增 Hypium 用例需在 DevEco 测试运行器中执行。

## 六、应用内提醒与执行前倒数（2026-09-27）

- `ScheduledEvent` 新增可选 `reminderEnabled`；新安排的日程默认开启，旧数据缺少字段时按开启处理。
- 月视图安排任务时，默认开始时间由整点吸附改为当前时间约 1 分钟后，方便快速验收；周/日视图仍以实际拖放时间为准。
- `CalendarTab` 在应用前台每秒检查日程：开始前 1 分钟内显示一次弱提示，开始前 20 秒弹出确认框。
- 新增 `UpcomingTaskDialog.ets`：展示“任务即将开始，确认开始吗”，底部提供实时更新的“确认（xx秒）”和“稍后”；归零自动进入执行准备流程，“稍后”固定延后 5 分钟。
- 日程详情页标题右侧新增“🔔 通知 / 🔕 已关闭”开关，并通过 `ScheduleStore.updateEvent()` 持久化；`updateEvent()` 同时通知日历刷新。
- 所有新执行会话在进入计时前先冻结第一步：页面由白色过渡到任务色背景并切换横屏，显示 3、2、1 后再恢复计时。继续已有会话不会重复倒数。
- 新增准备阶段单元测试，验证 3、2、1 期间第一步保持完整时长，结束准备后才开始扣减。
- 构建验证：`assembleHap` 完整通过，包含 ArkTS 编译、打包与签名；既有弃用 API 和兼容性提示仍为警告，不影响本轮构建。

## 七、周/日视图拖拽预览与落点校准（2026-09-28）

- 修复拖到 12:30 却安排到约 15:30 的偏差：`DragEvent.getY()` 返回的是窗口坐标，旧实现将页面标题栏等窗口偏移误算为时间；现在分别记录周/日时间轴可视区域在窗口中的顶部位置，再用“窗口拖拽点 - 时间轴顶部 + 当前滚动距离”计算真实时间。
- 使用 `getWindowY()` 替代已废弃的 `getY()`，明确坐标系并消除本轮相关弃用调用。
- 周视图和日视图都补上 `onDragMove`：拖拽进入或在时间轴内移动时，实时更新吸附后的开始/结束时间。
- 在目标日期列中加入虚线占位框：顶部对应开始时间，高度对应任务包总时长，颜色与任务包一致；在不同日期列间移动时只清理离开的旧列预览。
- 放下时与预览使用同一套局部坐标换算，因此滚动时间轴或双指缩放后，最终安排时间仍应与虚线框一致。
- 构建验证：`assembleHap` 完整通过，包含 ArkTS 编译、HAP 打包与签名；输出仅有项目既存的弃用 API / 兼容性警告，无新增编译错误。
